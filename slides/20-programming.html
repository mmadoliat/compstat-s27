“Premature Optimization Is the Root of All Evil”

  1. Correct first: write clear code; test it against known answers.
  2. Measure: benchmark alternatives, profile to find the bottleneck (usually one line).
  3. Improve the bottleneck: vectorize, preallocate, use better algorithms/data structures, call compiled code, parallelize.
  4. Re-test for correctness.

Tools: system.time(), microbenchmark, bench, Rprof(), profvis, object.size(), Rcpp, parallel.

Without Extra Packages: system.time() and Replication

timeit <- function(expr, reps = 200) {
  e <- substitute(expr); pf <- parent.frame()
  system.time(for (i in 1:reps) eval(e, pf))[["elapsed"]] / reps * 1e6     # microseconds
}
x <- rnorm(1e5)
c(sum_loop = timeit({ s <- 0; for (xi in x) s <- s + xi }, 20), sum_vectorized = timeit(sum(x)))
      sum_loop sum_vectorized

Preallocation and Vectorization

grow <- function(n) { v <- c(); for (i in 1:n) v <- c(v, i^2); v }        # copies every time!
prealloc <- function(n) { v <- numeric(n); for (i in 1:n) v[i] <- i^2; v }
vectorized <- function(n) (1:n)^2
n <- 2e4
rbind(grow = system.time(grow(n)), prealloc = system.time(prealloc(n)), vectorized = system.time(vectorized(n)))[, 1:3]
           user.self sys.self elapsed
grow           0.475    0.025   0.516
prealloc       0.004    0.000   0.003
vectorized     0.000    0.000   0.000
identical(grow(100), vectorized(100))
[1] TRUE

Growing an object inside a loop is \(O(n^2)\). Preallocate, or better, vectorize.

Loops in C++ Are Fast

A loop-heavy statistic: the random walk Metropolis sampler for a \(N(0,1)\) target.

cppFunction("
NumericVector rwMetropolisC(double sigma, double x0, int N) {
  NumericVector x(N); x[0] = x0;
  NumericVector u = runif(N);
  for (int i = 1; i < N; i++) {
    double y = R::rnorm(x[i - 1], sigma);
    if (u[i] <= exp(-0.5 * (y * y - x[i - 1] * x[i - 1]))) x[i] = y; else x[i] = x[i - 1];
  }
  return x;
}")
rwMetropolisR <- function(sigma, x0, N) {
  x <- numeric(N); x[1] <- x0; u <- runif(N)
  for (i in 2:N) { y <- rnorm(1, x[i - 1], sigma)
    x[i] <- if (u[i] <= exp(-0.5 * (y^2 - x[i - 1]^2))) y else x[i - 1] }
  x
}
set.seed(4750); N <- 2e5
rbind(R = system.time(xR <- rwMetropolisR(2, 0, N))[1:3], Cpp = system.time(xC <- rwMetropolisC(2, 0, N))[1:3])
    user.self sys.self elapsed
R        0.47        0   0.471
Cpp      0.01        0   0.010
c(mean(xC), var(xC))
[1] -0.003178  1.000973

Parallel Computing

Embarrassingly Parallel Simulations

Monte Carlo and bootstrap replicates are independent: split them across cores.

library(parallel)
ncores <- min(2, detectCores())
boot_med <- function(b, dat) median(sample(dat, replace = TRUE))
set.seed(4750); x <- rexp(200)
cl <- makeCluster(ncores)                       # works on Windows too (PSOCK)
clusterSetRNGStream(cl, iseed = 4750)           # reproducible parallel RNG streams
t_par <- system.time(r_par <- parSapply(cl, 1:20000, boot_med, dat = x))
stopCluster(cl)
t_ser <- system.time(r_ser <- sapply(1:20000, boot_med, dat = x))
rbind(serial = t_ser[1:3], parallel = t_par[1:3]); c(sd(r_ser), sd(r_par))
         user.self sys.self elapsed
serial       0.833    0.000   0.835
parallel     0.007    0.001   1.011
[1] 0.08506 0.08436
  • On macOS/Linux: mclapply(..., mc.cores = ) (forking). For reproducibility use RNGkind("L'Ecuyer-CMRG") streams.
  • Overhead matters: parallelize coarse tasks (thousands of replicates per worker), not single cheap calls.

Summary

  • Measure before optimizing: system.time(), microbenchmark, Rprof/profvis.
  • Preallocate, vectorize, avoid growing objects; work with integers vs doubles knowingly.
  • Compare objects with identical() / all.equal().
  • Read source code: print the function, methods(), getS3method(), :::, R sources for primitives.
  • Rcpp for loops that cannot be vectorized; parallel for independent replicates.
